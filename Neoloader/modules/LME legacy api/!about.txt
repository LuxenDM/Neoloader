!!!This is planning for a future potential problem, and is not implemented today! So far, the LME API has remained forward compatible. This is for the possibility that an API change breaks this compatibility streak.

================================================================================================

the Legacy API folder is for older editions of the LME API. If you need a specific behavior that has been removed from future editions of the API, then you can try to grab the older API behavior from the LME's class system with the ID of LME_LEGACY and the version of the API to be referenced. This may 

Suggested usage: Suppose you have a plugin that stopped working because the API changed. At the top of your file, you could try adding 


local lib = lib.get_class("LME_LEGACY", "3.12.0")
if lib.LEGACY_FLAG ~= "3.12.0" then
	error("API Mismatch")
end


Assuming that the older API is still being provided, you could get a little more life out of your plugin until it is updated to the new standard. Users will have to enable mod loading for API mismatch plugins though; by default, if the registration file itself doesn't match what the LME expects, it will not be loaded.

That being said, older copies of the API will NOT recieve support. If the change to the API is caused by a reorganization of function arguments or other implementation details, the plugin may continue to work. However, if the API is bumped to a new version because of changes to the core LME system, then the older API may stop working and eventually be removed.
